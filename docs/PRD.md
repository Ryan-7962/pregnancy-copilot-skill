# PRD: Pregnancy Copilot Skill v0.4.0

## 1. 问题

通用大模型已经能回答大量孕期问题，但孕期是一个持续数月、数据不断变化的过程：

- 换聊天窗口、模型或 Agent 后，上下文容易丢失。
- 同一检查指标的新旧值容易混淆。
- 症状、报告、医嘱、体重和待问医生问题分散在长对话中。
- 模型可能把缺失信息补全，或把未经确认的摘要当成事实。
- 真实孕期数据敏感，家庭需要掌握长期事实源和迁移权。

Pregnancy Copilot 的核心价值不是替大模型回答一次问题，而是让任意宿主 Agent 在整个孕期持续读取正确、最新、可追溯的上下文。

## 2. 产品定位

Pregnancy Copilot 是运行在 Hermes、OpenClaw、Codex、Claude Code 等宿主 Agent 内的长期孕期记忆与行为约束 Skill。

宿主 Agent 的 LLM 负责：

- 理解自然语言和用户意图；
- 判断医学相关性和回答问题；
- 在宿主支持时调用联网检索或其他工具。

Skill 负责：

- 本地保存原始输入和结构化事件；
- 管理带日期、来源、可信度和状态的医疗观测；
- 动态生成当前孕周和最小上下文；
- 保留历史变化和待确认候选；
- 提供少量确定性高危红旗兜底；
- 保证身份隔离、幂等写入、升级备份和可迁移性。

它不是医生、医疗器械、诊断或处方系统，也不是独立 App。

## 3. 用户

第一用户和数据所有者是孕妇本人。安装者可以是孕妇、伴侣或技术人员，但安装行为不自动授予其读取私密数据的权利。

v0.4.0 适合：

- 已使用通用 AI、但需要长期孕期记忆的孕妇；
- 希望为孕妇配置专属 Agent 的家庭；
- 需要可迁移、通道无关本地记忆层的 Agent 用户和开发者。

## 4. v0.4.0 必须实现

1. 首次安装后发送非阻塞欢迎；首轮及后续按状态提供回答优先、可跳过、不限轮数的微引导。
2. 建档允许多轮补充、未知和跳过；任何普通问题都能先回答，紧急问题优先分流且不展示教程。
3. 根据 LMP 或 EDD 动态计算孕周。
4. 所有有效入口消息加载最小上下文；普通闲聊不强制医疗化。
5. 医学语义以宿主 LLM 为主，确定性规则只做可审计的安全兜底。
6. 保存 raw inbox、结构化 events 和医疗 observation 时间线。
7. 新数据更新 current，旧数据保留；无日期或低可信记录只进入候选。
8. 高频日常数据按日期保存，并提供最近趋势。
9. 每位孕妇有独立数据根和明确入口绑定。
10. 消息和医疗写入支持幂等、并发保护、原子派生状态和安全路径。
11. 升级前创建可验证、可恢复的备份。
12. 提供宿主无关消息接口、安装检查、合成验收和干净发布包。
13. 提供每日对话归并、日志和紧凑索引；AI 整理摘要不能直接更新医学事实。
14. 提供带来源、改期历史和幂等提醒动作的本地产检计划。
15. 明确每日和提醒任务由宿主 Agent 或操作系统调度，Skill 本身不冒充常驻服务。
16. 识别小红书链接并提取可用文字/图片/视频内容，交由宿主 LLM 做来源和证据审计。
17. 外部内容永远不直接更新医学事实；Cookie/API Key 不进入聊天、pregnancy-data 或发布包。
18. 外部来源提供本地历史、相关性索引、“这条不记录”和默认媒体清理。

## 5. 非目标

v0.4.0 不承诺：

- 替代产科医生、急诊或正式医疗建议；
- 自动诊断、开药或修改医嘱；
- 完整 OCR 和无人工确认的报告入库；
- 独立移动端、网页后台或云数据库；
- 某个聊天通道开箱即用；
- 无需技术配置的消费级安装体验；
- 安装后自动获得后台调度、系统通知或任意聊天通道推送能力；
- 自动把私人数据同步给伴侣或第三方。
- 绕过社交平台登录、反滥用机制或支持任意网站抓取；
- 把热门帖子、个人经验或未核实医生身份当作医学证据。

## 6. 核心流程

1. 宿主通道提供可信入口身份和原始消息 ID。
2. Skill 解析身份并保存原始输入。
3. 无论建档是否完成，宿主先回答当前问题，再按状态附加最多一个教程主题；紧急红旗不附教程。
4. Skill 构建包含 profile readiness、当前状态、历史趋势和待确认项的 context package。
5. 宿主 LLM 判断医学相关性并生成最终回答。
6. 医学相关内容才进入风险判断、事件和观测写入。
7. 派生 current state、current context、日常趋势和可选作品可随时重建。
8. 宿主定时调用每日归并和提醒命令，并通过自己的默认通道发送返回动作。
9. 外部链接走独立审计动作：先提取，再由宿主区分原话、经验、商业信号、证据和适用性；不写医学 current。

## 7. 成功标准

- 切换模型或入口后，绑定到同一身份的 Agent 能读取同一份本地事实源。
- 普通闲聊能正常回答，但不会每句显示红黄绿。
- 新旧医疗值不会混淆，任何 current 值都能追溯来源。
- 不完整、无日期和低可信数据不会污染 current。
- 重复投递、并发和路径攻击不会导致静默丢失或越界写入。
- 两位孕妇共用一个宿主时，数据仍完全隔离。
- 公共仓库和发布包不含真实孕期数据、私聊、凭据或本机路径。
