# Open Questions

## Resolved for v0.1

1. 飞书文档写入最终使用飞书 CLI、官方 SDK，还是由宿主 Agent 工具调用？
   - v0.1 使用 `lark-cli` 适配器草案；飞书文档是展示层，不是主数据源。

2. v0.1 是否只实现 mock FeishuAdapter，还是直接实现真实飞书 API？
   - v0.1 同时有 mock adapter 和 `lark-cli` adapter；真实使用依赖用户自行配置飞书 CLI 权限。

3. 体重、血糖、用药提醒是否进入 v0.1 的代码实现，还是只定义 schema？
   - 不进入 v0.1 代码实现，放到 v0.3 工作流。

4. Gemini 历史导入器第一版支持哪一种 markdown 格式？
   - 支持 Kortex/Gemini markdown zip 中用长横线与 `🤖 Assistant` 分隔的格式。

5. 老婆端是否默认保存完整原文？是否需要初始化时确认？
   - v0.1 默认本地保存完整原文；公开产品化时应在初始化说明中明确告知。

6. 是否需要为不同任务配置不同 LLM？
   - v0.1 不绑定具体模型，只预留 `LLMProvider` 接口。

7. 飞书多维表格是否在 v0.1 创建，还是 v0.2？
   - 不在 v0.1 创建；后续作为展示/分析层。

8. 国际版产检流程是否只作为 Roadmap，不进入当前实现？
   - 是，不进入当前实现。

## Still Open

1. NotebookLM 导出格式是否稳定？是否需要人工清洗？
   - v0.1 只做 markdown 目录草案导入，全部标记人工复核。

2. Obsidian 知识库里的孕检 md 是否有固定命名规则？
   - v0.1 不要求固定命名；目录内 markdown 全量草案导入，用户人工复核。

3. 是否要在公开版初始化时强制用户确认“本地保存完整原文”？
   - 建议 v0.1.1 加交互式初始化或显式确认文档。

4. 是否要把飞书 CLI 安装和授权做成自动化脚本？
   - 建议 v0.1.1 做检查脚本，不自动替用户申请权限。
